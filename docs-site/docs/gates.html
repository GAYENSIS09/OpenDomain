The 9 gates

Nine questions you no longer get to forget.

A gate is not a form: it is a question asked at the right moment, with a machine-checkable answer. Each gate is a pure function — it reads the project, returns its verdict, touches nothing. Run it twice: same answer. And when it refuses, it cites the exact rule rather than a vague paraphrase.

The journey in nine stages

GateQuestionWhat's at stake
contextWhat are we building, for whom, under which constraints?The foundation: without it, everything else floats.
researchDid we really listen to the field?Dated, rated evidence, spotted contradictions, explicit end of research.
domainDoes the domain model hold together?Actors, rules, and processes coherent, each with an owner.
requirementsIs every requirement justified and testable?No requirement without upstream evidence or business rule.
opportunityDid we look for better than copying?Falsifiable, tested hypotheses; "no opportunity" is honorable.
specificationDo we describe the observable outcome, not the machinery?Behavior, acceptance criteria, error and boundary cases.
planIs the path bounded and ordered?Domain-derived architecture, sliced tasks, no cycles.
implementationDoes the code do what was promised?Vertical slices, tests first, no assumption disguised as certainty.
completionIs the whole chain coherent and tested?End-to-end final audit, plus simplification.
NoteThe opportunity stage deliberately comes after requirements: innovating before understanding the world produces feature lists. After, on a validated model of reality, you can tell "what the domain does" from "what we believe we can change". A regulated project may conclude no innovation is required.

Two possible verdicts

Blocking: you don't pass — the command fails, which makes a natural CI step. Advisory: reported without blocking. The paper specified three levels, the tool has two today, and the gap is documented in the paper itself: the framework applies its honesty requirements to itself.

To run a gate: od gate context, or od gate --through 3 to chain every gate up to requirements (--through takes the number 0–8, never the name). od reference prints the full dictionary of gates and record kinds.

The rules that tell the philosophy

The nine gates carry 63 named rules — 35 blocking, 28 advisory. Eight of them sum up the spirit:

RuleWhat it prevents
gate-3/unjustified-requirementA requirement out of nowhere: each one must cite its evidence.
gate-1/orphan-evidenceAn assertion with no author: evidence without a source is not evidence.
gate-1/single-sourceFake corroboration: a single origin, however repeated, proves nothing.
gate-8/assumption-reached-productionAn assumption shipped to users.
gate-5/how-not-whatA specification narrating machinery instead of outcome.
gate-4/unfalsifiable-hypothesisA hypothesis that can never be settled: metric and threshold required.
gate-4/feature-cloning"We're doing it because others do it."
gate-7/epistemic-launderingRepainting doubt as certainty — the queen rule, see Concepts.
