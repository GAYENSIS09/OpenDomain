Getting started

Install the tool, create a project, get your first verdict.

Prerequisites

You need Rust 1.75 or newer. A single build is enough; afterwards the binary is self-contained.

Install

The recommended way, with Rust installed:

cargo install --git https://github.com/GAYENSIS09/OpenDomain --locked opendomain-cli
od --version

Prefer building from source? That works too — the binary lands at target/release/od.exe (Windows) or target/release/od (Unix):

git clone https://github.com/GAYENSIS09/OpenDomain
cd OpenDomain
cargo build --release

Put the binary on your PATH, or call it by its full path.

Initialize a project

od init doesn't create code: it prepares a tidy workbench — an opendomain/ folder of 41 files (33 registries, 7 explanatory documents, and opendomain.toml describing the project), plus an agent contract (AGENTS.md and the .opencode/ files). Re-run, it reports what already exists without overwriting anything.

mkdir my-bookstore && cd my-bookstore
od init --name my-bookstore
od status
TipThree profiles cover common situations: full (everything, default), core (no innovation stage, for systems with an imposed scope), and lean (the domain model already lives elsewhere). --dry-run shows what would be created without writing anything. To take over an existing system, prefer --repository brownfield: current code is treated as a clue there, not a specification.

Read your first verdict

At first, gates fail — that's their job. od status gives the project weather (what is ready, what is blocked), od gate context returns the first gate's verdict with what's missing, and od audit reports traceability health. Every refusal cites the exact rule: read it as an instruction, not a reproach.

Once two records are linked, try od trace (why does this requirement exist?) and od impact (what would need revisiting if this rule changed?). That's the moment the framework "clicks". Command details live in the CLI reference.
