CLI reference

Four intents: locate, link, ask, evolve.

Locate — where do we stand?

od status                 # project weather: real progress + blockers
od gate context           # verdict of one specific gate
od gate --through domain  # every gate up to the domain model
od audit                  # traceability health report
od reference              # dictionary: gates + 37 record kinds

status every morning, gate before each stage, audit before saying "done".

Link — declare dependencies

od link --check                         # does every link point to something real?
od link REQ-012 derived-from EVD-014    # this requirement comes from this evidence
od advance REQ-012 VALIDATED            # move a record to validated state
od show REQ-012                         # full record of one artifact

Whoever depends always declares the link.

Ask — why, and what if it changes?

od trace REQ-012                    # walk back to the source: the "why"
od trace --forward REQ-012          # walk down: who implements and verifies it
od impact RULE-007                  # what a change would invalidate
od graph --root REQ-012 --depth 3   # the neighborhood, to see the web

Evolve — change without rewriting history

od propose tighter-reservation --summary "Tighten the reservation window"
od apply tighter-reservation
od archive tighter-reservation

Propose, apply, archive. Even refuted hypotheses are kept: a deleted failure gets re-derived, an archived failure teaches.

Global options and CI

--json yields machine-readable reports on every reporting command, and a blocking gate fails the command — od gate --through specification --json > gate-report.json makes a CI step. --no-color and -C <dir> work everywhere.

Check the workshop itself

cargo test --workspace      # 118 unit tests + 2 doctests
cargo fmt --all -- --check

The workshop: crates/opendomain-core/ (model, parser, index, graph, gates) and crates/opendomain-cli/ (the od binary).
