With opencode

The same assistant, with a work contract.

Point opencode at a project containing an opendomain/ folder: it inherits commands, roles, and a discipline of evidence. You keep the AI's creativity; the framework imposes honesty on it — when it doesn't know, it writes UNKNOWN instead of inventing.

Reading commands

CommandRole
/od-statusWhere the project stands, and what is blocking — in ten seconds.
/od-gateRuns one gate and reports the verdict as is, without softening it.
/od-traceTells a record's origin from its recorded links.
/od-impactLists what a change would invalidate, before touching code.
/od-auditFull health report before declaring "done".

One command per stage

CommandStageWhat it does
/od-projectContextReads the repo, researches the domain, fills in the context, asks you the rest.
/od-researchResearchFans out parallel research and merges corroborated evidence.
/od-recordAnyWrites one record while staying epistemically honest.
/od-domainDomainGrows the model by one bounded increment.
/od-requirementsRequirementsDerives a small batch of justified, testable requirements.
/od-opportunityOpportunityChallenges the design, earns one falsifiable concept.
/od-specSpecificationSpecifies one capability as observable behaviour.
/od-planPlanProduces one bounded, ordered plan with decisions.
/od-implementImplementationBuilds one scoped artifact through the craftsperson.
/od-completeCompletionReuses the audit, then calls the release: ship or stop.

Every command answers summary-first — verdict, top blockers, one next action — with the tool's full output in an appendix. No wall-of-gates noise.

Three roles

context-completer, the interviewer. Owns Phase 0 context: it reads the repository itself, delegates external research to the investigator, then asks you what no reading could answer. Brought in by /od-project.

domain-researcher, the investigator. It reads, searches, and reports only dated sources and evidence, fanning out in parallel by keyword. Called by the interviewer, /od-research, /od-domain, and /od-requirements. By default it can hardly execute anything — except od * to check its own work.

spec-implementer, the craftsperson. One scoped task against an existing specification, with a gate check before and after. If it steps out of scope, the gate catches it. Called by /od-implement.

Five skills

The framework's know-how, loaded on demand by commands and roles:

SkillLoad it when…
opendomainYou need the shared discipline and the map to the other four.
opendomain-epistemicsChoosing a knowledge value, recording a promotion, checking laundering.
opendomain-artifactsWriting or repairing any record — format, ids, relations.
opendomain-researchGathering evidence — parallel search, triangulation, saturation.
opendomain-gatesReading any gate, status, or audit output — identifier to action.
TipCommands are thin routers (user experience), roles call each other (interviewer → investigator → craftsperson), skills carry the know-how. Run the command for the stage you're in; it loads the right skill and delegates to the right role.

Noteopencode reads its configuration at startup: restart it after any addition. AGENTS.md is never overwritten, even with --force. od init never writes opencode.json: copying the permission above remains your decision.
