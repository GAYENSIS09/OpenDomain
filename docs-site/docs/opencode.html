With opencode

The same assistant, with a work contract.

Point opencode at a project containing an opendomain/ folder: it inherits commands, roles, and a discipline of evidence. You keep the AI's creativity; the framework imposes honesty on it — when it doesn't know, it writes UNKNOWN instead of inventing.

The six commands

CommandRole
/od-statusWhere the project stands, and what is blocking.
/od-gateRuns a gate and reports the verdict as is, without softening it.
/od-traceTells a record's origin from its recorded links.
/od-impactLists what a change would invalidate, before touching code.
/od-auditHealth report before declaring "done".
/od-recordWrites a record while staying epistemically honest.

Two roles

domain-researcher, the investigator. It reads, interviews, and reports only dated sources and evidence. By default it can hardly execute anything — except od * to check its own work.

spec-implementer, the craftsperson. One scoped task against an existing specification, with a gate check before and after. If it steps out of scope, the gate catches it.

Permissions: read freely, change by agreement

{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "bash": {
      "od *": "allow",
      "od init *": "ask",
      "od link *": "ask",
      "od advance *": "ask",
      "od apply *": "ask",
      "od archive *": "ask"
    }
  }
}
Noteopencode reads its configuration at startup: restart it after any addition. AGENTS.md is never overwritten, even with --force. od init never writes opencode.json: copying the permission above remains your decision.
